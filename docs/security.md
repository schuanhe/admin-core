# 安全边界与运行约束

## 管理员

- 首次创建需要单独高熵初始化令牌；数据库唯一约束防止并发创建第二个管理员。
- 密码使用 bcrypt，长度12到72字节，数据库不保存明文密码。
- 会话由密码学随机数生成，只存会话SHA-256摘要；浏览器cookie为HttpOnly、SameSite=Strict，可配置Secure，有效期默认12小时。
- 登录/初始化按真实TCP来源限速，不信任任意客户端提供的转发头；反向代理后所有请求可能共用一个限速桶，应在入口补充适当策略。
- 所有管理接口要求有效会话，并检查浏览器Origin与Sec-Fetch-Site；写接口另外要求CSRF，不在localStorage保存认证凭据。无Origin的服务端客户端仍须提供对应会话与写操作CSRF，Origin不是身份凭据。
- 初始化、登录失败/成功、登出、登记、启用禁用、删除、检查和设置更改保留审计。日志不记录请求正文、cookie、Authorization、密码或密钥。

## 注册与页面

- 注册入口使用独立随机密钥，验证成功后才解析受限请求体。密钥只交给受信任服务；本版不隔离各服务的注册身份，持有共享密钥者可更新允许的任意服务id，不能将其提供给不受信任租户。
- 注册 JSON 严格字段白名单、版本、大小、结构与重复键检查，数据事务写入；非法定义不污染旧记录。
- 页面与组件使用固定白名单：table/form/detail/compose及中心内置组合组件。页面内容字符串不执行，不注入模板、HTML、脚本或远程模块。
- 浏览器业务请求只去同源中心网关；管理员会话与CSRF双校验，CSP connect-src限制为self。页面没有URL、方法或凭据控制权，独立业务令牌不返回浏览器。
- 网关读取只在服务端保存的每服务origin／路径／方法策略，仅调用页面定义与策略的交集；服务端再验证独立业务令牌和中心真实来源IP。
- 独立服务的业务返回值是非可信文本，验证与渲染错误只影响该页。
- 服务CSS是惰性配置数据，前端挂载前使用CSSTree AST校验并给每个选择器添加唯一页面边界；禁止全局at-rule、外部资源、脚本与穿透选择器，卸载时移除。页面边界采用布局/绘制/层叠隔离，不接受服务样式覆写；声明式style通过相同属性值规则。实际支持名单由接入手册接口提供。
- CSS语义在浏览器检查，Go只校验字段形状、大小与编码并保存，不把CSS注入任何服务端模板。无效CSS会在对应页面显示错误，不会退回全局注入，也不会影响管理接口。

## 后端网络

- 中心不提供任意URL抓取或通用反向代理；受限JSON业务网关的接入协议见后台可开关的GET /api/v1/integration/handbook。
- 健康检查只能访问已登记且在部署白名单中的origin；注册不能修改部署白名单。
- DNS地址解析后逐个检查并固定实际拨号IP，阻止DNS重绑定窗口；禁止元数据、链路本地、多播、未指定和部分保留地址；不使用环境HTTP代理，不跟随重定向。
- 允许配置中的私网/回环地址是工作站场景的显式授权，并非允许任意内网扫描。不要加入不受控DNS域名或可转发任意目标的服务。
- 健康检查超时3秒、最多4路并发；业务调用超时6秒、最多8路并发，业务响应最多1MiB，HTTP总超时15秒。单服务停机不删除其登记/设置。
- 业务令牌只通过服务端HTTPS传输；HTTP仅允许实际回环地址。响应不透传Cookie、Location、认证头或上游错误正文。业务写操作在调用前后保留审计，不自动重试。

## 运维责任

生产使用HTTPS、Secure cookie、受限端口、防火墙和独立备份；配置与数据库只授权必要系统账户。示例业务API已改为独立令牌与来源IP双校验，仍不应暴露公网。不要将生产密钥放入源码、构建参数、前端环境变量或镜像层。Compose通过只读文件挂载业务策略、运行时环境注入中心注册凭据；能读取配置或Docker进程环境的人仍应视为受信任管理员。

后台每小时清理过期会话，审计保留最近10000条、每服务注册事件保留最近100条（详情展示最近30条）。这是固定轻量策略，不是合规归档系统；如需长期留存，应自行定期备份数据库。

第一版是单管理员、单实例、个人受信任工作站产品，提供文件配置的服务业务令牌，不提供在线令牌签发、自动轮换、多租户隔离、MFA、密码找回、自动安全更新或公共插件执行沙箱。若未来扩大到公网多人环境，需要单独威胁建模和认证升级。本次改动按要求未运行测试，不能视为已完成安全审计。

## 本轮静态检查（2026-10-23）

- 检查路由绑定：服务列表、详情、状态修改、删除、检查、设置、导航排序、审计和业务网关均使用后端会话校验，不依赖前端导航守卫；注册独立校验注册密钥。公开接口包含基本健康状态、初始化状态及各自受令牌/限速保护的初始化和登录入口；另外有管理员显式开启时才返回通用资料的接入手册接口。
- 收紧读取接口的来源检查，避免只防写入而遗漏管理数据与CSRF令牌的跨站读取边界。
- Vite开发入口固定回环监听，禁用开发CORS，文件服务范围显式限制为web目录，不允许读取上层数据库及服务密钥文件。仅通过5173同源入口调试，不将开发端口暴露到公网。
- 图标与面包屑采用前后端字段白名单和本服务页面引用校验，不接受HTML、脚本或外部链接。
- 网关仍要求启用状态、页面定义与部署接口白名单交集、独立服务令牌；示例业务端保留真实TCP来源与Bearer认证。健康接口仅返回状态，不需要业务令牌。
- 当前范围是本地可信服务管理；共享注册密钥仍不提供服务身份隔离，本轮不扩展跨服务器管理。未来开放远程注册前，应改为每服务独立身份并重新审查网络与TLS策略。

本轮只阅读和修改代码，没有运行测试套件、渗透检查或依赖漏洞扫描；以上不构成“没有安全漏洞”的保证。

## 接入手册与导航偏好

- GET /api/v1/integration/handbook默认关闭。管理员在系统设置保存开关，受会话、来源和CSRF保护，并写入审计与SQLite。开启后Markdown和JSON都无需登录；关闭后每次请求重新检查数据库，统一返回404，不允许管理员会话绕过，不缓存手册授权结果。
- 手册只从静态组件注册表、Go协议类型和占位示例生成，不读取实际Config、ServiceAccess、服务记录或凭据。响应no-store，未开启CORS，不改变其他管理与注册接口的认证要求。已下载的内容无法远程撤回。
- PUT /api/v1/service-navigation同样要求管理员会话和CSRF，校验标识、数量和重复项，事务保存顺序/固定状态并审计；注册JSON没有这些字段，服务不能自行置顶。禁用不丢偏好，删除服务时偏好随登记一并删除。
